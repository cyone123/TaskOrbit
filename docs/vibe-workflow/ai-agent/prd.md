# 需求规格说明书 (PRD): TaskOrbit AI Agent 任务助理

## 1. 背景与目标 (Background & Goals)

### 1.1 背景
TaskOrbit 目前已具备完善的本地任务管理、项目分解、每日计划甘特图/时间块、番茄钟专注追踪以及统计看板体系。然而，在日常自我管理中，用户依然面临以下挑战：
1. **收集碎片整理负担重**：快速捕获到收集箱中的灵感与杂务，手动整理为项目任务、设定优先级与截止日期操作链条长。
2. **日程排期凭直觉与静态预估**：计划制定往往未能精准考虑当日可用空隙，突发任务延误后缺乏灵活重排手段。
3. **数据沉淀缺乏主动洞察**：番茄钟和任务流转沉淀了大量时间与执行记录，但缺乏智能化、有针对性的效能诊断与复盘反馈。

### 1.2 核心目标
构建 TaskOrbit 的 **AI Agent 辅助任务管理与执行助理**，支持接入主流大语言模型（LLM），通过标准化的工具调用（Tool Calling），打通“读取应用数据 → 综合推理分析 → 生成建议/计划 → 人机协同确认 → 写入应用状态”的闭环，打造懂用户习惯的高效个人效率幕僚。

## 2. 目标用户与使用场景 (Users & Scenarios)

### 2.1 目标用户
- 重视个人效能管理、善用番茄钟与日程规划的知识工作者、开发者与学生。
- 追求数据自主可控，习惯本地离线优先，同时希望借助现代大模型提高规划与复盘效率的用户。

### 2.2 典型用户旅程与场景

#### 场景 1：收集箱碎片智能结构化整理
- **前置**：用户在收集箱中碎片化记录了数条笔记与待办（如：“周五前向团队汇报技术方案”、“给家里买牛奶”、“深入学习 Rust 并发编程第4章”）。
- **流程**：用户在收集箱点击顶部【AI 整理】按钮或在侧边栏对 Agent 说“帮我整理收集箱”。Agent 调用只读工具获取未处理条目与现有项目列表，分析优先级、识别截止时间与建议归属项目。
- **反馈与确认**：Agent 在对话中展示交互式【变更确认卡片】（包含转为任务/计划的详细字段）。用户点击【确认应用】，系统调用 `mutate` 自动创建对应任务/计划并更新/归档收集箱条目。

#### 场景 2：智能日程排期与动态重排
- **前置**：用户开启新的一天，或者上午任务超时导致下午计划被打乱。
- **流程**：用户对 Agent 说：“今天下午有 3 小时空档，帮我把项目 A 中最紧急的任务排进今天的日程”或“下午的会议延长了，帮我顺延后面的计划”。
- **反馈与确认**：Agent 检索已有每日计划时间块与待办任务列表，避开冲突，计算最优时间段，生成排期调整方案。用户预览时间块变更卡片后点击确认，日历视图即时联动更新。

#### 场景 3：效能反思与时间分配洞察
- **前置**：用户在周末或每日晚间希望了解近期专注度与进度偏离情况。
- **流程**：用户在统计页面点击【AI 效能反思】或在对话中发起询问。
- **反馈**：Agent 读取过去 7/30 天的番茄钟会话记录、各项目耗时分布及每日计划完成率，输出深度诊断：
  - 识别黄金专注时段（如：“专注度集中在上午 9:00-11:30，下午番茄钟中断率偏高”）；
  - 揭示时间预估偏差与瓶颈（如：“项目 B 实际耗时远超预估，每日计划完成率不足 60%”）；
  - 提供 2-3 条切实可行的下一周期排期与执行改进策略。

#### 场景 4：全局灵活多轮对话
- **流程**：用户可在任意视图通过快捷键或导航栏呼出右侧抽屉，针对当前任务进度进行自由提问（如“下周有哪些即将截止的高优任务？”、“帮我构思‘重构认证模块’的子任务拆分步骤”），Agent 流式解答。

## 3. 需求范围与边界 (Scope & Exclusions)

### 3.1 包含在内 (In-Scope for V1)
1. **模型供应商接入**：
   - 采用标准 OpenAI 兼容协议（支持自定义 Base URL、API Key、Model Name、Temperature 等）；
   - 内置常用厂商快捷预设（DeepSeek、硅基流动 SiliconFlow、OpenAI、通义千问、Ollama 本地模型等）；
   - 提供连接测试（Connection Test）功能与错误提示；
   - API Key 本地安全持久化，数据导出脱敏。
2. **界面交互形态（桌面端优先）**：
   - 全局右侧可折叠抽屉（Chat Drawer），支持折叠/展开、宽度微调与快捷键（如 `Ctrl/Cmd + J`）；
   - 流式响应打字机效果（SSE）、支持 Markdown 渲染与代码高亮；
   - 消息历史记录持久化（支持新会话、清空历史）；
   - 快捷上下文唤起：在收集箱、日历、统计页面提供显式的“AI 整理/排期/反思”引导动作。
3. **Agent 核心与工具调用系统**：
   - 协议与工具抽象下沉至 `@task-orbit/core`，保证跨平台可复用性；
   - **只读工具（自主执行）**：
     - `get_workspace_summary`: 获取整体工作区概要（项目概况、今日计划、待办量）；
     - `get_inbox_items`: 读取未处理或特定收集箱条目；
     - `get_projects_and_tasks`: 读取项目列表及任务详情；
     - `get_daily_plans`: 查询指定日期区间的每日计划时间块；
     - `get_pomodoro_stats`: 聚合查询番茄钟专注记录与历史统计；
   - **写操作工具（Human-in-the-loop 确认卡片）**：
     - `plan_inbox_organization`: 提案将收集箱转为任务或计划；
     - `plan_task_mutations`: 提案创建、修改任务；
     - `plan_schedule_daily_plans`: 提案创建、调整或顺延每日计划时间块；
   - 所有写入由用户在 UI 卡片点击【确认执行】后调用 core domain 纯函数执行，并通过 Zod 严格校验。

### 3.2 明确排除 (Explicit Exclusions for V1)
1. **移动端 AI UI 界面**：首期专注于在桌面端验证完整体验，移动端界面将在后续版本跟进（底层 core 模块保持通用）。
2. **Obsidian Vault 深度向量检索 (RAG)**：首期不引入本地 Embedding 模型或向量数据库，专注于结构化任务、计划与番茄钟数据。
3. **全自动静默写操作**：严禁 AI 未经用户授权直接静默修改或删除任务，杜绝幻觉造成的数据丢失。
4. **语音对话交互**：暂不集成 TTS/STT 模块。

## 5. 非功能需求 (Non-Functional Requirements)

1. **界面美学与 MD3 规范**：
   - 侧边栏及所有卡片必须严谨使用 MD3 设计令牌（`surface-container` 层次、`primary` 强调色、`outline-variant` 描边等）；
   - 自适应深色（Dark Mode）与浅色（Light Mode）模式；
   - 交互具备平滑过渡动画与统一 Focus-visible 态。
2. **状态与数据完整性**：
   - 遵循 TaskOrbit 单一 `AppState` 范式，所有写入必须经由 `domain.ts` 的纯函数和 Zod Schema 校验，杜绝非法引用。
3. **安全与隐私控制**：
   - 用户数据仅在执行查询时按需发送给用户所配置的 LLM 端点，不搭建任何中转中间件；
   - API Key 严禁在日志中明文打印，导出配置文件时自动过滤。
4. **健壮性与容错能力**：
   - 面对模型输出的畸变 JSON、网络中断或超限错误，给出友好的中文提示与“重试”按钮，不阻断主界面操作。

## 6. 可观察验收标准 (Acceptance Criteria)

- [ ] **AC-1 (模型接入)**：用户在设置中配置有效 API Key 与模型名称，点击“测试连接”返回成功；配置异常时给出清晰错误提示。
- [ ] **AC-2 (界面交互)**：点击顶栏 AI 图标或快捷键可顺畅展开/收起 AI 侧边栏；对话支持流式打字与随时中止。
- [ ] **AC-3 (效能反思)**：在包含历史番茄钟和计划的数据下请求效能反思，Agent 自动调用相关工具，输出包含时间分配与改进建议的报告。
- [ ] **AC-4 (收集箱整理)**：在收集箱有待办时触发整理，Agent 返回结构化方案卡片，用户点击“应用”后，对应项目下新增任务且原收集箱条目状态更新。
- [ ] **AC-5 (日程排期)**：要求 Agent 排期今日任务，Agent 输出日历时间块建议卡片，确认后日历视图正确显示新增的 `DailyPlan`。
- [ ] **AC-6 (安全脱敏)**：通过数据管理导出备份时，生成的 JSON 中不包含 API Key。
